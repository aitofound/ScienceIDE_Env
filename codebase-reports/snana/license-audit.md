# SNANA wfit source and licensing audit

Audit date: 2026-09-16. Source revision: `f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1` of [RickKessler/SNANA](https://github.com/RickKessler/SNANA/tree/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1). Scope: the upstream `wfit.exe` build and the small benchmark wrapper being prepared here. This records located evidence and unresolved terms; it does not assign a new license to SNANA.

## Result

SNANA is intentionally public scientific software. Its manual explicitly says that making code modifications does not require prior permission from the primary developers. This supports proceeding with local installation, examination, and benchmark development. It would be inaccurate to describe the project as simply prohibiting modification because a top-level license file is absent.

However, the checked revision does not contain a repository-wide `LICENSE`, `COPYING`, or `NOTICE` file, and the README does not specify a software license. GitHub's repository API returned `private: false` and `license: null` during this audit. No matching license-file history or license/copyright/redistribution commit message was found in the available full local Git history. These observations do not establish that permission has never been given elsewhere. They do mean that a blanket MIT/BSD/GPL license for all SNANA code, or comprehensive permission to redistribute a compiled container, has not been verified.

## Direct project evidence

- The [2009 SNANA paper](https://arxiv.org/abs/0908.4280) describes a public software package. The [pinned README](https://github.com/RickKessler/SNANA/blob/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1/README.md) provides build instructions and identifies the move to public GitHub in May 2019.
- The [manual's contribution section](https://github.com/RickKessler/SNANA/blob/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1/doc/snana_manual.tex#L460-L477) encourages changes to be integrated upstream and says advance permission for modifications is unnecessary. The paragraph does not set out a general redistribution license.
- The [manual's citation section](https://github.com/RickKessler/SNANA/blob/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1/doc/snana_manual.tex#L440-L456) requests credit for SNANA and underlying scientific work. The [wfit source introduction](https://github.com/RickKessler/SNANA/blob/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1/src/wfit.c#L24-L69) explains its SNLS/SDSS origin, later contributors, scientific references, and requested identification of the SNANA cosmology grid-search program in publications.
- The [Zenodo record linked from the README](https://zenodo.org/records/12655677) is for **SNDATA_ROOT data, models, and ancillary files**, not a blanket license for the SNANA source repository. Its metadata cannot be used to license `wfit.c` by inference.
- [GitHub's own licensing documentation](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository) distinguishes the platform's permission to view/fork a public repository from a software license permitting broader use and distribution. SNANA's explicit modification statement is additional evidence and should be retained alongside this distinction.

## Code actually involved

The [pinned build target](https://github.com/RickKessler/SNANA/blob/f7ad9ad6a1f58d7c550b646d9aeb86a9e8c34eb1/src/Makefile.am#L617-L628) links `wfit`, `sntools`, `sntools_output`, `sntools_npz`, `cnpy`, and `sntools_cosmology` objects, plus external libraries. `sntools.c` includes `eispack.c` and `uthash.h`; `sntools_output.cpp` includes additional output implementation files. A single chosen executable therefore has more source provenance than `wfit.c` alone. The complete compiler dependency closure should be retained when publishing a source inventory.

## Minimal deliverable supported by the evidence

1. Finish the local benchmark, including a pinned-source fetch/build script, generated fixtures, checker, tolerances, validation results, and this source record. Credit SNANA and wfit. Do not add a fabricated SNANA license identifier to the task metadata.
2. Keep upstream source, downloaded archives, and built executables in ignored working directories. A reviewable submission can contain the original wrapper, source commit/hash, links, reproducible download/build instructions, and independently generated data. This narrows what the new repository redistributes; it does **not** resolve all downstream rights or guarantee the benchmark accepts this packaging form.
3. Treat publishing a container containing upstream code/executables, or vendoring that source into ScienceAccelBench, as a separate packaging decision. Before that final distribution, resolve the applicable upstream and embedded third-party terms and include the required notices/source materials. Using a small source subset or a submodule does not by itself establish a new redistribution grant.
4. If ScienceAccelBench requires a repository-level license declaration, record the status as unverified/manual permission statement located and give the evidence to its curator. Do not claim that the absence of an automatically detected license prevents all local progress.

Only read-only inspection and this report were performed by this audit. No author was contacted, no issue or message was posted, and no upstream file was modified. The old SNANA site and several third-party documentation endpoints could not be fetched during this bounded review; no permission claim relies on their unavailable contents.
