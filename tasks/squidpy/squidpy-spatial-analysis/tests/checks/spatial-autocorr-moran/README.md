# spatial-autocorr-moran

来源为 `code/squidpy/tests/graph/test_ppatterns.py::test_spatial_autocorr_reproducibility[moran-1]`。官方那组test只断言返回表的列数、两次运行的 `pval_norm` 一致，以及置换p值在不同种子下不一致。本check保留同一fixture与同一调用，但把整张确定性结果表作为完整数值观测：列数与自比一致几乎不排除任何错误实现。

Moran's I 衡量的是相邻观测的表达值是否同向偏离均值，取值围绕期望 `-1/(n-1)`；本fixture上正负都有。

## 原输入与域内variant

`ic/nominal/input.npz` 冻结官方 `dummy_adata` fixture（`tests/conftest.py:109-118`）：`RandomState(100)` 的200×100 float64表达矩阵，以及 `spatial_neighbors(n_rings=2)` 生成的空间邻接图（float32，1200个非零，全部为1.0）。邻接图连同基因与观测身份一起以CSR三元组存进初值，因此check运行时不再调用那个已被标记弃用的构图入口，也不受它未来变化的影响。

生产器调用 `spatial_autocorr(mode='moran', n_perms=None, n_jobs=1, transformation=True, corr_method='fdr_bh')`。`n_perms` 保持 `None`：置换p值依赖RNG与线程数，官方自己在注释里承认它在 `n_jobs` 之间不可复现，因此不进入评分。

variant只把原表达矩阵的 `[obs=102, gene=5]` 向正无穷 `nextafter` 两次，仍在原 `(0, 1)` 域内。这个点不是随手挑的：先用与源码无关的解析杠杆对全部20000个位置排序，再用真实kernel逐个验证。实测 `moran_i`、`pval_norm` 与 `pval_norm_fdr_bh` 各1值活动，最大差分别为2.0816681711721685e-17、2.220446049250313e-16与2.7755575615628914e-16，最差占暂拟界限的9.76e-06；`var_norm` 只依赖邻接图，不随表达值变化，因此不活动。

## 完整输出合同

`result.npz` 必须且只包含以下五个成员。

| 成员 | 形状 | 意义 |
|---|---|---|
| `gene` | `(100,)` | 唯一字符串基因身份 |
| `moran_i` | `(100,)` | 逐基因的Moran's I |
| `pval_norm` | `(100,)` | 正态假设下的p值 |
| `var_norm` | `(100,)` | 正态假设下的方差，**float32** |
| `pval_norm_fdr_bh` | `(100,)` | BH校正后的p值 |

源码返回的表按统计量排序，行序是数据相关的离散结果；评分一律按 `gene` 身份对齐，因此任何行序都可接受，排序本身不参与判定。p值与其BH校正值是概率，必须落在 `[0,1]`；`var_norm` 必须严格为正。validator在原dtype下先检查有限性与这些区间，再转float64比较。

## 界限与输出精度地板

暂拟 `pointwise`：`moran_i` 为 `atol=1e-12, rtol=1e-10`；`var_norm` 为 `atol=1e-9, rtol=1e-6`；两列p值为 `atol=1e-6, rtol=1e-6`。

`var_norm` 由源码以float32存储与计算，0.00146 附近的float32间距约1.16e-10，任何比它更紧的界限都会把存储精度当成科学错误。更关键的是p值：源码把**float32的方差直接开方**得到标准误，而其中的 `s0`/`s1`/`s2` 本身也是在float32下对1200条边与40000项累加得到的。本批有两条实测证据——用float64开方的独立实现与源码的p值相对差达1.31e-07；把邻接图整体提升到float64这一合法的更高精度实现，使p值绝对平移最多3.15e-08。因此两列p值的界限对齐这条链路的输出精度地板1e-6，而不是压到本次测得的两ULP spread（1e-16量级）。

地板有具体来源、可复算，但**不是**此前写在这里的那条。原先的说法是「邻接图 6-正则、权重全 1.0，行归一化就是除以 6，float32(1/6) 的相对误差 2.9802322443206464e-08 经方差传到 p 值」——**这条在数学上不成立**，已作废。反证：Moran 的 V 在权重整体缩放 w→c·w 下精确不变（分子分母同乘 c²），而 1200 个权重是同一个值、float32(1/6) 的相对误差是均匀的，等价于一次缩放，**必然恒等抵消**；实测 c=1/6 与 c=6 时 V 的相对变化分别是 0 与 0，就是 float64 噪声。同样地，float64-graph 与 no-row-normalisation 两个探针 bound_fraction 逐位相同（0.1418305155566018）**是这条尺度不变性的推论、是一条定理，不是机制成立的证据**——那两张图之间只差一个均匀因子 6。把定理当证据是循环论证，当时是我写错了。 真机制（已独立复核，一阶模型精确到 7 位有效数字）：float32 图上 _g_moments 的**累加**误差，经 V 对各阶矩的条件数放大。实测三个矩的相对误差 s0=-7.62939e-08、s1=-6.99303e-09、s2=-4.95516e-08（s0 是 199.99998474121094 而不是 200，三者各不相同所以不抵消）；V 的有符号条件数 |∂V/∂s_i·s_i/V| 为 s0=-1.932、s1=1.036、s2=-0.07019，**主导项是 s0**（它以 4·s0² 进入被减项）。逐项相加预测 V 的相对误差 1.43629e-07，直接实测 float32 图 vs float64 图为 1.43629e-07，预测/实测 = 0.9999999。作废的那条只预测 2.9802322443206464e-08，比实测小 4.82 倍。 为什么这不只是措辞：作废的那条把「6-正则、权重 1.0」说成了承重条件，用到别的 fixture 上会系统性地把界限设窄；真机制在任何图上都存在，且随条件数变差。**放宽到 1e-6 的决定本身与数值都不变，改的只是归因。**

**要看清界限有多紧**：那个合法的 float64-graph 实现通过时占掉了界限的 **0.1418305155566018**，也就是只有约 7.1 倍余量。作者的意见是最终界限不应低于当前值，并建议人工考虑再放宽一个数量级到 `atol=1e-5` 附近；这一条留给人工定夺，作者没有自行改数。

统计量本身是float64。`atol=1e-12` 远小于本fixture里两个基因Moran's I之间最小的间隔4.47e-05，因此不会把两个基因混为一谈；`pval_norm` 最接近的一对间隔9.44e-05，BH校正的秩也不会被浮点差异改变。所有界限均为假设，未经最终批准。

## 运行与独立自测

`run.sh nominal|variant` 只用自己的输入、指定只读源与已安装依赖，不安装或联网。`--help` 列出 `SAB_THREADS=1`、`SAB_PYTHON=python3`；保留官方200×100规模与 `n_jobs=1`。输出目录必须为空；没有altbuild，请求它退出2。stdout里的mode、规模、图的非零数与"返回表确实是排过序的"只是路径日志，不参与评分。

`python3 selftest.py` 运行19个只依赖标准库与NumPy的独立 `unittest` 方法，多数含具名子例。它用人为构造的payload测试三种随机行序都必须通过、基因绑定错位与列互换都被抓到、概率越出 `[0,1]` 与方差为零或负在任一侧都被拒、恰好取到0.0与1.0仍被接受、绝对界限的两侧，以及一个float32量级的p值相对平移必须通过而1e-4量级必须失败；不读取真实初值、HOME、生产源码或其它check。比较与strict ASCII JSON、UTF-8编码受普通 `Exception` guard保护，失败写全新 `passed:false, fields:{}` 并保留stderr traceback；取消信号与真实输出I/O错误不被吞掉。

## 输入观测重排：合法摆放差异的独立证据

本 check 的 legal-reordering 重排的是**输出**的身份轴，测的是 validator 不看存储顺序（距离恒为 0）；这里重排的是**输入**观测——200 个观测换一个存放顺序，表达矩阵行与邻接图两个轴同步置换，仍是同一张图（度序列与权重集合逐一核对不变）——测的是 float32 归约次序对数值的真实影响。两者名字像，测的是两回事。

实测**是活跃的**：`moran_i` 100 值中 94 值变、最大差 1.249000902703301e-16；`pval_norm` 73 值变、最大差 5.551115123125783e-16；`pval_norm_fdr_bh` 94 值变；整体 distance 5.551115123125783e-16，占暂拟界限的 **2.6422663030595473e-05**，通过。

机制值得记一笔：`var_norm` 逐位不变，但底层的 s1 在置换下确实动了（60.61111068725586 → 60.611114501953125，约 6.3e-08 相对，正是 float32 量级），它回到 float32 后被量化吸收，所以归约次序只经由 float64 的逐基因求和传到结果。比值已按舰队新规则移出本 check 的合同文本，只留在工作记录 `~/.sciaccel_pipeline/squidpy/quantisation-ruler.json` 里。规则：**比值只允许用于 graded 输出本身是离散的观测量**（标号场 / 集合 / 名次 / 边集），禁止作为任何连续容差决策的输入，**包括作为前置筛**。理由比规则本身重要：要安全地读这个比值，你必须先知道条件数；而一旦你有了条件数，比值就不再增加任何信息——**所以它永远不承重**。触发它的是 LIANA+ 的实测：比值判「会被吸收」的那个观测量，端到端条件数是 528.66（放大 529 倍），**给最危险的那个发了通行证**。本 check 的 graded 输出是连续量，因此适用移出。（SAB_RULER_SCOPE_2026_09_11）

因此重排的影响比 float64-graph 那条小约 5367 倍（2.6422663030595473e-05 vs 0.1418305155566018）——**界限的约束项仍然是 float64-graph 那条**。这是界限可达性的第二份独立证据。

## 实测与明确盲点

本批正例先RED后GREEN，生产器另有一组与源码无关的独立重实现（自写的行归一化、Moran's I公式、Cliff & Ord正态方差与BH校正）交叉核对全部输出。成功nominal只执行一次并保留复用，墙钟7.716秒、最大RSS 524708 kB；variant为7.895秒、526136 kB，均含Python导入与numba首次编译。域内两ULP的活动见上；完整payload按随机置换重排后距离0通过。这些不是Docker selfcheck，也不是跨平台floor。

独立scratch源码探针完整返回后由数值判定。被拒的有：把 `two_tailed` 默认值改成 `True` 时两列p值各100值越界、最大差0.4867（统计量完全不动）；把多重比较校正换成Holm却仍标成 `fdr_bh` 时只有 `pval_norm_fdr_bh` 100值越界、最大差0.5898。这两条正好说明只评分统计量会漏掉整类错误。

**两条编辑经实测并不改变科学量，如实记录：**

- 跳过权重行归一化（`transformation` 分支置假）。官方fixture的邻接图恰好**正则**：`nnz/n = 1200/200 = 6`，每个观测都有且只有6个邻居。行归一化因此是一个精确的一致缩放，在 `(n/s0)` 与 `s0` 里完全约掉，正态方差的 `s0/s1/s2` 同阶缩放后也约掉。实测统计量最大差只有9.02e-17，p值残差落在float32精度地板之内。**所以本fixture无法分辨行归一化是否执行**——这是初值的结构性质，没有为补这个洞改初值或把界限压到噪声以下。
- 把邻接图提升到float64。这是合法的更高精度实现，按设计通过，最大差3.15e-08。

其它盲点：本case只覆盖 `n_jobs=1` 的确定性路径，不约束置换p值、并行分块、`attr='obs'/'obsm'` 入口、非默认 `transformation`/`corr_method`/`two_tailed` 的取值组合，也不约束 `use_raw` 与 `layer`。p值界限对齐float32精度地板，因此1e-7量级以下的实现差异一律不可分辨。
