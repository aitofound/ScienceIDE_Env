# ex-anisopressure-fastwave

Upstream test: `code/swmf/GM/BATSRUS/Param/ANISOPRESSURE/PARAM.in.fastwave`. Policy: `pointwise`.

## The test

run.sh follows the same recipe as the module's Makefile.test targets (configure, build, make rundir, copy the initial condition in as PARAM.in, run on 2 MPI ranks, PostProc.pl -m). This deck is an upstream example with no Makefile.test target of its own, so the configuration is derived from the deck and from its sibling test_anisotropic: nine state variables ending in Ppar and P fix the MhdAnisoP equation set, and #CHECKGRIDSIZE (or, where the deck has none, the sibling test) fixes the 100x2x2 block with two ghost layers and the fast update path. This example is the only check in the module that switches #ANISOTROPICPRESSURE itself on: the instability-driven pitch-angle scattering that relaxes the pressure anisotropy towards the firehose and mirror thresholds, on top of the plain CGL update the other anisotropic checks exercise, together with the #ENTROPY update path. The window t=1 is upstream's and is the graded default; SAB_TMAX_SCALE multiplies it.

In the declared 4-cpu container the run takes about 14 s on its 2 MPI ranks, after a
source build of about 68 s that `run.sh` reports separately as `SAB_BUILD_SECONDS` and that the
suite budget does not count. `run.sh --help` lists the knobs. `SAB_TMAX_SCALE` (default 1.0) multiplies tSimulationMax and scales the run time linearly; `SAB_MPI_RANKS` (default 2) and `SAB_BUILD_JOBS` (default 4) change the decomposition and the build parallelism. The defaults are the graded values.



Under the 2026-09-13 window revision, `run.sh` also rewrites the graded `#SAVEPLOT` cadence of the '1d var idl_ascii' series from `SAB_PLOT_FRAMES` (default 10; cadence = window / SAB_PLOT_FRAMES, in the deck's time unit). The graded series writes 11 frames (measured); `run.sh` fails if fewer than 5 are written. `SAB_PLOT_FRAMES` is listed by `run.sh --help` alongside the existing knobs.

## The two initial conditions

`ic/nominal` is the upstream parameter file `code/swmf/GM/BATSRUS/Param/ANISOPRESSURE/PARAM.in.fastwave`, unchanged. ic/variant raises the #UNIFORMSTATE density from 1.0 to 1.0000000002, two units of the tenth significant digit of the printed output, which shifts the fast-wave speed, the advection and every relaxation source term. The two PARAM.in files differ byte-wise and the graded outputs differ. `run.sh altbuild` runs ic/nominal on the alternative build: the same Config.pl configuration built with `./Config.pl -O0` before `make BATSRUS`, which sets every OPTn level of Makefile.conf to -O0 where the shipped gfortran template uses -O3 (same pinned source, same deck).

## The pass policy

The policy is `pointwise`: every number of every graded file is compared with the reference under |candidate - reference| <= atol + rtol * |reference|, with **rtol = 1e-5** and **atol = 1e-07**. The step number, the simulation time, the grid size and the equation parameters at the head of every frame are numbers too and are compared under the same rule, so a run that reaches the window in a different number of steps is caught; the description and variable-name lines are text and must match exactly, so a candidate that renames or reorders variables, or writes a different number of frames or cells, fails before any value is compared. rtol = 1e-5 is the relative tolerance upstream's own `share/Scripts/DiffNum.pl` comparison uses for this module's tests, and it is what carries the bound for the large-magnitude variables; atol is the floor for the components that sit at round-off in this configuration, where a relative bound would be meaningless. The bound is physical. The wave is launched with different amplitudes in P (0.16) and Ppar (0.14) on top of an already anisotropic background, and `#ANISOTROPICPRESSURE` with UseConstantTau and both relaxation times set to -1 puts the instability-driven pitch-angle scattering in charge of relaxing the anisotropy towards the firehose and mirror thresholds. An implementation that drops that relaxation, or that advances a single pressure, leaves Ppar and Pperp on different trajectories and changes the advected profile at t=1 by order 1e-2, five orders of magnitude above atol. It is achievable: this configuration is explicit with no decomposition-dependent reduction, so two legitimate runs of the same executable on 2 and on 4 MPI ranks are bit-identical over every graded number, and the only measured movement is the two-ulp variant, 1e-9 after about 2400 steps. atol=1e-7 is a hundred times that.

## Evidence

**Floor.** Two legitimate runs of the same executable and the same `ic/nominal`, one on 2 MPI ranks and one on 4, differ by at most 0 in absolute value over every graded number (`make rundir` once from the build this check's run.sh produces, then `mpiexec -n 2 ./BATSRUS.exe` and `mpiexec -n 4 ./BATSRUS.exe` on the same PARAM.in, compared value by value over the graded file). **Two-ulp spread.** The same measurement between `ic/nominal` and `ic/variant` on 2 ranks gives 1e-09, and after the 1e-5 relative term the smallest atol that would still pass is 8.923e-13; the declared atol=1e-07 is about 100 times the measured spread. **Self-validation.** The tolerance was set from these numbers before the calibration run and confirmed by the recorded self-validation; `comment/pipeline/self-validation.json` and the `evidence.self_validation_spread` field of `rubric.json` carry the Docker-side spread measured inside the oracle image. **Alternative build.** The -O0 altbuild (./Config.pl -O0 before make BATSRUS, same source and deck) is bit-identical to the -O3 nominal build over every graded value. The reference outputs themselves are never described here.
