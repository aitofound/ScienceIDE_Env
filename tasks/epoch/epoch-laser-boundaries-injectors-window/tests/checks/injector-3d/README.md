# injector-3d

Upstream test: `code/epoch/epoch3d/example_decks/injectors.deck`. Policy: `invariants`.

## The test

`run.sh` builds the pinned tree's epoch3d binary once and runs the shipped 3-D `injectors` example deck coarsened to 64x16x16 cells instead of 128x32x32 and to 0.02 s instead of the deck's 0.3 s, with the dump cadence coarsened from 0.005 s to 0.01 s; every one of those is restorable through a knob and all four are the reductions the 2-D injector check makes for the same reason, that the deck at its shipped size does not finish inside a three-minute check. What three dimensions add over the 2-D check is the second transverse axis of the injector: the per-cell depth accumulator is a rank-2 array indexed on both transverse directions, the weight of a created particle carries a third cell dimension, and the loop that places each new particle across the face runs over two perpendicular directions rather than one. The knobs are `SAB_NX`, `SAB_NY`, `SAB_NZ`, `SAB_T_END`, `SAB_DT_SNAPSHOT`, `SAB_PPC` and `SAB_MAKE_JOBS`; the official values are `SAB_NX=128 SAB_NY=32 SAB_NZ=32 SAB_T_END=3.0e-1 SAB_DT_SNAPSHOT=0.5e-2`.

## The two initial conditions

`ic/nominal` is the shipped deck with `nprocx = 2, nprocy = 2, nprocz = 1` written in, the coarsened grid and window where this check coarsens them, and the knob markers. `ic/variant` differs on exactly those rank-layout lines: `nprocx = 1, nprocy = 1, nprocz = 4`, a different valid decomposition of the same domain over the same number of ranks' worth of work. EPOCH's generator is a 32-bit integer KISS seeded 7842432 + rank (`src/housekeeping/random_generator.f90`, `src/housekeeping/setup.F90`), so a different decomposition draws this deck's per-cell random stream in a different order: a correct, equally valid realisation of the same physics, and exactly what a differently parallelised or vectorised port would also produce. That is the point of the variant after the round-2 redesign -- the earlier variant perturbed the deck's density constant by five ulps and deliberately stayed on the same random stream, which tested rounding but not robustness to reordering. A THIRD decomposition (`nprocx = 2, nprocy = 1, nprocz = 2`) was run by hand through this check's own `run.sh` and `extract.py` on 2026-09-06 on the x86_64 worker, so every graded statistic below has three correct realisations behind it rather than two; the largest pairwise spread among those three is what sets each bound. `run.sh` also accepts `altbuild`, which runs `ic/nominal` unchanged on the same shipped gfortran build one optimisation level down (`-O0` in place of `-O3`, `epoch3d/Makefile` line 72 in the scratch build copy only), the same pinned source and deck; EPOCH's own `MODE=debug` profile was tried first and rejected because it aborts with SIGFPE inside Open MPI's own `mpi_minimal_init` before any EPOCH arithmetic runs.

## The pass policy

The policy is `invariants` (round-2 steward review item 4, curator option A): the flux injector and the background loader draw particle positions and momenta from EPOCH's seeded stream, so a correct implementation that consumes the same physical stream in a different per-cell order produces a different realisation, and grading the per-cell arrays value by value would fail it. What is graded instead are invariants of the loading. Physical: `run_single_injector` (`epoch3d/src/physics_packages/injectors.F90`) creates the beam on the x_min face once per step, before the particle push. Per transverse cell it forms `npart_ideal = npart_per_cell * v_inject * density_correction * dt / cell_size`, subtracts a Box-Muller-jittered `npart_ideal` from a per-cell depth accumulator and releases `FLOOR(ABS(depth - 1))` particles when the accumulator goes negative; each new particle gets weight `vol*density/npart_per_cell`, a position uniform across the transverse cell and a distance behind the face proportional to a uniform draw times `v_inject*dt`, and a momentum drawn flux-weighted along the injection direction and Maxwellian across it. For this deck the drift momentum 2.5e-24 kg m/s is 42.7 times the thermal momentum sqrt(m*kb*273), so the code takes its large-drift branch: `density_correction` is exactly 1 and `v_inject` is the drift velocity p/(gamma*m) = 2.744e6 m/s, 0.00915c. The deck's own analytic flux expectation follows from that: over 16x16 = 256 transverse cells with dx = 2.5e5/64 = 3906.25 m the injector should release `ppc * ny * nz * v_inject * t / dx` = 14388 macroparticles by the first graded dump (0.01 s) and 28776 by the second (0.02 s), and the domain transit time 0.0911 s is far beyond the graded window so nothing leaves. The measured increment between the two graded dumps matches that analytic per-interval flux to 0.7 percent; the absolute counts sit below the free-flight integral by an offset that does not grow between the two dumps. The graded statistics are the total injected macroparticle count and number integral per graded dump; the background load's mean number density and its coefficient of variation across cells; the injected momentum distribution's weighted mean and variance and the L1 distance between its normalised histogram and the reference's; the Ex RMS, integrated Ex^2 and integrated |Jx| the beam drives in the background; and the coefficient of variation of the injected per-cell count across the (y,z) injection face, which the deck's transversely uniform density makes a genuine uniformity invariant. A mis-scaled `dt/cell_size`, a library `erf` in place of the code's own `density_correction`, a weight that forgets a cell dimension or a momentum sampler that draws the wrong distribution all move these aggregate statistics by O(1) or more, while a legitimate reordering of the same per-cell draws does not. Bounds: the injected count and number integral are relative (rtol 0.02 and 0.03 at the first graded dump, 0.05 at the second) because they scale with the deck's density, cell volume and window; the background mean density is held at rtol 1e-12 (the three layouts agreed to one ulp of a reduction over 16384 cells); the background uniformity CV has atol 0.003 and the injection-face CV atol 0.015; the momentum mean and variance rtol 0.001 and 0.2; the momentum histogram L1 distance 0.1; and the Ex RMS, Ex^2 energy and |Jx| integrals rtol 0.005, 0.01 and 0.05. Every bound is the smallest 1/1.5/2/3/5/7 x 10^n value that is at least four and at most ten times that statistic's largest pairwise spread over the three rank layouts measured on 2026-09-06 (the measured headroom per statistic is 4.0x to 6.5x, and each bound carries a one-line `_bound_note` in `rubric.json`). Poisson-scale scatter sits inside those count bounds: the graded populations are about 1.1e4 and 2.6e4 macroparticles, so sqrt(N) is 106 and 160 and the count bounds are 2.1x and 8.0x that. This is the largest sample of the three injector checks and carries the sharpest versions of the same statistics: the momentum mean at rtol 0.001 and the Ex^2 energy at rtol 0.01 would catch a drift, weight or coupling error of a fraction of a percent, orders of magnitude inside an O(1) fault in the injector's rate, weight or sampler.

## Redesign, 2026-09-06 (round-2 steward review, item 4; curator option A)

Moved from `pointwise` to `invariants`. EPOCH's flux injector and the seeded
background loader draw particle positions and momenta from EPOCH's seeded
KISS stream (7842432 + rank); at a FIXED rank layout two correct runs
consume that stream identically, which is what the previous pointwise
per-cell/per-bin comparison relied on. A differently parallelised or
vectorised, equally correct implementation can consume the same physical
stream in a different per-cell order (this leaf's concrete, measurable
instance of that is a different MPI rank layout), which the old policy
would fail despite correct physics. `extract.py` now writes scientific
invariants of the loading -- total injected count/charge per dump, the
background load's mean density and uniformity, the injected momentum
distribution's mean/variance and its normalised-histogram L1 distance from
the reference, aggregate field/current moments, and (2-D/3-D) the
transverse per-face uniformity of the injected count -- instead of the raw
per-cell arrays and the raw momentum histogram bins. `ic/variant` is now
the deck's rank layout changed to a different valid decomposition (was: a
five-ulp density-constant perturbation that deliberately stayed on the same
random stream, which does not exercise robustness to reordering). No check
was added or removed and the graded dumps are unchanged. Bounds were set on 2026-09-06 from the measured realisation spread (see below).

Extractor fix, 2026-09-06 (measured on the worker against real SDF dumps): the dist_fn/x_px block's direction1 = dir_x is a spatial direction, so despite `resolution1 = 1` in the deck EPOCH still writes it as an (nx, 200) block tied to the actual grid, not a flat 200-bin array (measured: 25600 bins for nx=128 in injector-1d, 12800 for injector-2d/3d). `extract.py` now sums (marginalises) the block over the spatial axis before computing the momentum mean/variance and before writing `beam_dist_shape.f64`, which grades the 1-D momentum histogram's shape (the L1 distance between normalised probability mass functions), not the raw 2-D x-px occupancy -- the marginal-momentum option of the two the round-2 review offered, chosen because the observable text and warrant above already describe a momentum distribution, not a joint x-px one.

## Bounds, 2026-09-06

The provisional bounds this check carried between the redesign and the calibration are gone. Every bound above was set from the realisation spread measured across THREE valid MPI rank layouts of this deck on the x86_64 worker on 2026-09-06 (the two shipped in `ic/` plus a third run by hand through this check's own `run.sh` and `extract.py`), using the convention this project's physics-packages leaf uses: four to ten times the largest measured spread per statistic, relative where the quantity scales with the deck, absolute where it does not, and tight to round-off where the quantity is deterministic. The per-statistic numbers behind each bound are in `comment/probes/rank-layout-spread-20260906.json`.
