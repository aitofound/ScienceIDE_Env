# injector-1d

Upstream test: `code/epoch/epoch1d/example_decks/injectors.deck`. Policy: `invariants`, flagged chaotic.

## The test

`run.sh` builds the pinned tree's epoch1d binary once and runs the shipped `injectors` example deck, unchanged apart from an explicit two-rank layout, a quieter stdout, a dump cadence coarsened from 0.005 s to 0.05 s, and an end time halved to 0.15 s. The deck puts a flux injector on the x_min face: a 273 K beam drifting at 2.5e-24 kg m/s is created there every step at eight macroparticles per cell and streams into a background of the same species that is a thousand times denser and drifts the other way. That is an unstable configuration by construction, which is what makes it a good test of the injector (the beam has to be created correctly for the instability to grow correctly) and also what forces a short graded window. The graded statistics are picked to separate the failure modes: the total injected count and number integral test the flux accumulator against the deck's own analytic flux, the background load's mean density and uniformity test the load the beam is injected into, the momentum mean, variance and histogram shape test the momentum sampling, and the aggregate Ex and Jx moments test the coupling back to the fields. None of them is a per-cell or per-bin comparison; see the pass policy below. The knobs are `SAB_NX`, `SAB_T_END` (the deck's own value is 3.0e-1), `SAB_DT_SNAPSHOT`, `SAB_PPC` and `SAB_MAKE_JOBS`. The check takes 55 s, most of it the one build.

## The two initial conditions

`ic/nominal` is the shipped deck with `nprocx = 2` written in, the coarsened grid and window where this check coarsens them, and the knob markers. `ic/variant` differs on exactly those rank-layout lines: `nprocx = 1`, a different valid decomposition of the same domain over the same number of ranks' worth of work. EPOCH's generator is a 32-bit integer KISS seeded 7842432 + rank (`src/housekeeping/random_generator.f90`, `src/housekeeping/setup.F90`), so a different decomposition draws this deck's per-cell random stream in a different order: a correct, equally valid realisation of the same physics, and exactly what a differently parallelised or vectorised port would also produce. That is the point of the variant after the round-2 redesign -- the earlier variant perturbed the deck's density constant by five ulps and deliberately stayed on the same random stream, which tested rounding but not robustness to reordering. A THIRD decomposition (`nprocx = 4`) was run by hand through this check's own `run.sh` and `extract.py` on 2026-09-06 on the x86_64 worker, so every graded statistic below has three correct realisations behind it rather than two; the largest pairwise spread among those three is what sets each bound. `run.sh` also accepts `altbuild`, which runs `ic/nominal` unchanged on the same shipped gfortran build one optimisation level down (`-O0` in place of `-O3`, `epoch1d/Makefile` line 72 in the scratch build copy only), the same pinned source and deck; EPOCH's own `MODE=debug` profile was tried first and rejected because it aborts with SIGFPE inside Open MPI's own `mpi_minimal_init` before any EPOCH arithmetic runs.

## The pass policy

The policy is `invariants` (round-2 steward review item 4, curator option A): the flux injector and the background loader draw particle positions and momenta from EPOCH's seeded stream, so a correct implementation that consumes the same physical stream in a different per-cell order produces a different realisation, and grading the per-cell arrays value by value would fail it. What is graded instead are invariants of the loading. Physical: `run_single_injector` (`epoch1d/src/physics_packages/injectors.F90`) creates the beam on the x_min face once per step, before the particle push. Per transverse cell it forms `npart_ideal = npart_per_cell * v_inject * density_correction * dt / cell_size`, subtracts a Box-Muller-jittered `npart_ideal` from a per-cell depth accumulator and releases `FLOOR(ABS(depth - 1))` particles when the accumulator goes negative; each new particle gets weight `vol*density/npart_per_cell`, a position uniform across the transverse cell and a distance behind the face proportional to a uniform draw times `v_inject*dt`, and a momentum drawn flux-weighted along the injection direction and Maxwellian across it. For this deck the drift momentum 2.5e-24 kg m/s is 42.7 times the thermal momentum sqrt(m*kb*273), so the code takes its large-drift branch: `density_correction` is exactly 1 and `v_inject` is the drift velocity p/(gamma*m) = 2.744e6 m/s, 0.00915c. The deck's own analytic flux expectation follows from that: the injector releases `ppc * v_inject * t / dx` macroparticles per transverse cell, and in one dimension the domain of 2.5e5 m is crossed in 2.5e5/2.744e6 = 0.0911 s, before either graded dump (0.10 s and 0.15 s), so the beam population is in steady state and the analytic expectation is the fill `ppc * nx = 8 * 128 = 1024` macroparticles rather than the free-flight integral (1124 and 1686 at those two times); the measured counts sit a few percent above 1024 at both graded dumps, which is the transit-time fill the deck predicts, and the beam's simple_outflow x_max face is what removes the difference. The graded statistics are the total injected macroparticle count and number integral per graded dump; the background load's mean number density and its coefficient of variation across cells; the injected momentum distribution's weighted mean and variance and the L1 distance between its normalised histogram and the reference's; the Ex RMS, integrated Ex^2 and integrated |Jx| the beam drives in the background; and there is no transverse injection face in one dimension, so no face-uniformity statistic. A mis-scaled `dt/cell_size`, a library `erf` in place of the code's own `density_correction`, a weight that forgets a cell dimension or a momentum sampler that draws the wrong distribution all move these aggregate statistics by O(1) or more, while a legitimate reordering of the same per-cell draws does not. Bounds: the injected count and number integral are relative (rtol 0.07 at the first graded dump and 0.2 and 0.3 at the second) because they scale with the deck's density, cell volume and window; the background mean density is a uniform-weight load of a fixed macroparticle count, so it is the deck's own constant whatever order the draws come in and is held at rtol 1e-12, reduction-order room over the grid; the background uniformity CV has atol 0.03; the momentum mean and variance rtol 0.3 and 3; the momentum histogram L1 distance 1.5; and the Ex RMS, Ex^2 energy and |Jx| integrals rtol 1, 1.5 and 0.7. Every bound is the smallest 1/1.5/2/3/5/7 x 10^n value that is at least four and at most ten times that statistic's largest pairwise spread over the three rank layouts measured on 2026-09-06 (the measured headroom per statistic is 4.0x to 6.5x, and each bound carries a one-line `_bound_note` in `rubric.json`). Poisson-scale scatter sits inside those count bounds: the graded population is about 1.1e3 macroparticles, so sqrt(N) is about 33 and the count bounds are 2.3x and 6.7x that. This is the small-sample check of the three: at about 1.1e3 injected macroparticles the realisation spread of the field, current and momentum-variance moments is tens of percent, so their bounds only reject order-of-magnitude faults, and the L1 histogram bound had to be capped at 1.5 of the statistic's own maximum of 2 (four times the measured spread would have exceeded that maximum), which makes it a gross-shape test here. The discriminating statistics in one dimension are the injected counts and charges and the exact background density; the 2-D and 3-D injector checks, with 6x and 25x the sample, carry the sharp versions of the same statistics. The long-window behaviour of the same injector -- the steady-state balance between injection and outflow -- is what this check adds over them.

## Redesign, 2026-09-06 (round-2 steward review, item 4; curator option A)

Moved from `pointwise` to `invariants`. EPOCH's flux injector and the seeded
background loader draw particle positions and momenta from EPOCH's seeded
KISS stream (7842432 + rank); at a FIXED rank layout two correct runs
consume that stream identically, which is what the previous pointwise
per-cell/per-bin comparison relied on. A differently parallelised or
vectorised, equally correct implementation can consume the same physical
stream in a different per-cell order (this leaf's concrete, measurable
instance of that is a different MPI rank layout), which the old policy
would fail despite correct physics. `extract.py` now writes scientific
invariants of the loading -- total injected count/charge per dump, the
background load's mean density and uniformity, the injected momentum
distribution's mean/variance and its normalised-histogram L1 distance from
the reference, aggregate field/current moments, and (2-D/3-D) the
transverse per-face uniformity of the injected count -- instead of the raw
per-cell arrays and the raw momentum histogram bins. `ic/variant` is now
the deck's rank layout changed to a different valid decomposition (was: a
five-ulp density-constant perturbation that deliberately stayed on the same
random stream, which does not exercise robustness to reordering). No check
was added or removed and the graded dumps are unchanged. Bounds were set on 2026-09-06 from the measured realisation spread (see below).

Extractor fix, 2026-09-06 (measured on the worker against real SDF dumps): the dist_fn/x_px block's direction1 = dir_x is a spatial direction, so despite `resolution1 = 1` in the deck EPOCH still writes it as an (nx, 200) block tied to the actual grid, not a flat 200-bin array (measured: 25600 bins for nx=128 in injector-1d, 12800 for injector-2d/3d). `extract.py` now sums (marginalises) the block over the spatial axis before computing the momentum mean/variance and before writing `beam_dist_shape.f64`, which grades the 1-D momentum histogram's shape (the L1 distance between normalised probability mass functions), not the raw 2-D x-px occupancy -- the marginal-momentum option of the two the round-2 review offered, chosen because the observable text and warrant above already describe a momentum distribution, not a joint x-px one.

## Bounds, 2026-09-06

The provisional bounds this check carried between the redesign and the calibration are gone. Every bound above was set from the realisation spread measured across THREE valid MPI rank layouts of this deck on the x86_64 worker on 2026-09-06 (the two shipped in `ic/` plus a third run by hand through this check's own `run.sh` and `extract.py`), using the convention this project's physics-packages leaf uses: four to ten times the largest measured spread per statistic, relative where the quantity scales with the deck, absolute where it does not, and tight to round-off where the quantity is deterministic. The per-statistic numbers behind each bound are in `comment/probes/rank-layout-spread-20260906.json`.
