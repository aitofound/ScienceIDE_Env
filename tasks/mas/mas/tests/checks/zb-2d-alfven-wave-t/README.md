# zb-2d-alfven-wave-t

Upstream test: `code/mas/testsuite/zb_2d_alfven_wave_t`. Policy: `pointwise`.

## The test

run.sh runs a zero-beta 2D (nr 105, nt 100, np 3) analytic Alfven wave in theta (initial_field ALFVEN_WAVE1, wave_mode_r 2, wave_mode_t 3, amplitude 1e-4) advanced to t 14.9875 with viscosity 1e-5 and no resistivity (slund 1e30), 600 steps of dtmax 0.025. It exercises the vector-potential advance (adva, src/mas.F90:25557) and the semi-implicit viscous velocity solve (advv 36556, v_solver 38232, cgsolve 26899) on a phi-degenerate 2D mesh. The deck is the testsuite deck with tmax lowered from 15.0 to 14.9875 (599.5 x dtmax) so the run ends inside the 600th step instead of on its boundary; the same 600 steps as upstream. The knobs and their graded defaults: SAB_TMAX=14.9875 (the window), SAB_FRAMES=5 (output cadence SAB_TMAX/5), SAB_MPI_RANKS=4. The build is made once per source digest and build mode and cached under SAB_BUILD_CACHE_ROOT (solve.sh mounts a host directory), so the fourteen checks of one solve share one -O2 build (and, in the selfcheck, one -O1 build). The graded build is -O2, not upstream's -O3: the image's gfortran 14.2 on x86_64 produced NaN in the first semi-implicit velocity solve of the WTD deck at -O3, while -O2, -O1 and -O3 without the tree vectoriser all ran it. Measured natively: 6 s on 4 ranks; the rubric's expected_runtime_s is that number and the calibration selfcheck records the container time.

## The two initial conditions

ic/nominal is the deck as described. ic/variant raises the viscosity `visc` by two ulps of double precision (1.e-5 to 1.0000000000000004e-05); the semi-implicit viscous solve then converges to a state that differs from nominal at the round-off level in every field (native needed tolerance 2.312e-11), which is the kind of perturbation the pointwise bound must admit. run.sh altbuild builds the same source with `-O1` instead of the graded `-O2` and runs the nominal deck on it (native needed tolerance 2.059e-11).

## The pass policy

Every value of the energy history (history_a.txt), the first eleven columns of history_b.txt and the 6 graded frames of br,bt,bp,vr,vt,vp (with their mesh coordinates) must satisfy |candidate - reference| <= 1e-07 (|reference| + peak |reference| of the file): 1e-07 of the value, with a floor of 1e-07 of the field's own peak where the field crosses zero (the peak_rtol term of validate.py; the fields of one deck span many orders of magnitude, so one absolute atol cannot serve them). The bound is physical because a wrong Alfven speed, a dropped viscous term or a looser CG tolerance changes the wave amplitude decay at the 1e-4 level of the wave itself; the graded fields are the perturbed br, bt, bp, vr, vt, vp, which is far above 1e-07. It is achievable because two legitimate runs of the pinned build differ only through the reorder of the CG reductions (`src/mas.F90:26899` cgsolve, `global_sum` at 46419), compiler contraction and the solver's own convergence tolerance (epscg 1e-9): the two-ulp variant needs 2.312e-11 and the -O1 build 2.059e-11, and in the x86 calibration container the variant needs 1.956e-11 while the -O1 build is bit-identical, so the bound sits 4325x above the largest of the three. The energy histories are printed with eight significant digits, so no bound below 1e-7 can be met by them once a legitimate run flips their last digit. The columns dt, Flow_CFL and Wave_CFL of history_b.txt are not graded: they are the time-step bookkeeping of the run, not physics.

## Evidence

Native measurements (arm64 macOS, gfortran 15.2, Open MPI 5.0.8, 4 ranks, the same run.sh): nominal 6 s; nominal vs variant needs 2.312e-11; nominal vs -O1 altbuild needs 2.059e-11 (needed tolerance = max over graded values of |d| / (|ref| + peak |ref|)); the -O0 build measured the same spread as -O1 to two digits at five times the run time. Calibration selfcheck on the x86 worker (2026-09-16, 4 cpus, gfortran 14.2, Open MPI, Debian trixie image): run time 6 s; nominal vs variant max |d| 3.001e-15 using 1.956e-04 of the bound of that run (1e-07; the final selfcheck re-records the fraction against the bound above); the -O1 altbuild bit-identical to the -O2 build in every graded value (floor 0 on x86_64). The record is comment/pipeline/self-validation.json.
