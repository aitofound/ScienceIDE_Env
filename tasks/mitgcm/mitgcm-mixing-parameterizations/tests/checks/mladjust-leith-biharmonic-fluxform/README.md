# mladjust-leith-biharmonic-fluxform

Upstream test: `code/mitgcm/verification/MLAdjust/input.A4FlxF`. Policy: `pointwise`.

## The test

Biharmonic Leith viscosity in the flux-form momentum equations, from a pickup. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/MLAdjust: a 50x26x40 zonally re-entrant channel closed by a wall at the northern edge (four tiles of 25x13 under pkg/exch2, uniform 1 km horizontal spacing and forty uniform 5 m levels, 52000 cells and the largest grid in this module's suite), started from a mixed-layer density front given by thetaInitial.bin with salinity carried as a passive spice tracer (spiceInitial.bin, sBeta=0) and a flat bottom from topo_sl.bin, with no forcing of any kind, f-plane at f0=7.29e-5, a linear equation of state, third-order direct-space-time flux-limited advection for both tracers, vertical viscosity viscAr=5e-5, ivdc_kappa=10 with implicit diffusion for convection, useJamartWetPoints, stagger time stepping, an implicit free surface with cg2dTargetResidual=1e-11 and no explicit horizontal background viscosity at all, so that the entire lateral momentum mixing is whatever the flow-dependent closure returns; the input.A4FlxF overlay drops vectorInvariantMomentum, so the momentum equations are integrated in flux form by pkg/mom_fluxform with the flux-form viscous operator, and leaves no_slip_sides at its default of true so that lateral side drag acts on the channel walls, while keeping the same purely biharmonic flow-dependent viscosity as the base deck (useFullLeith with viscC4leith=1.85 and viscC4leithD=1.85, viscC4smag=1, capped by viscA4GridMax=1 with no background viscA4); it is the only deck of the experiment that restarts, from pickup.0000000036 at nIter0=36, so it begins from a front that has already adjusted for twelve hours rather than from rest; the window is 6 steps of 1200 s, two hours, half the upstream twelve-step window and a small fraction of the ten-day endTime the base deck records as its production option, kept short for the measured reason given in the warrant..

The production path it forces: pkg/mom_common/mom_calc_visc.F forming the biharmonic Leith, Leith-divergence and Smagorinsky coefficients, and pkg/mom_fluxform (mom_fluxform.F with mom_u_del2u.F, mom_v_del2v.F and the biharmonic wrappers) applying them in flux form, with model/src/calc_ivdc.F, model/src/impldiff.F and the third-order flux-limited tracer advection of model/src/gad_dst3fl.F making up the rest of the step..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 6, the graded
value; the upstream deck runs 12 steps of 1200 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.A4FlxF/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useMNC=.FALSE.` in `data.pkg`; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `viscC4leith=1.8500000000000005` in `data` instead of 1.85:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump plus the momDiag and viscDiag files that dumpAtLast writes at the final iteration, graded relatively with an absolute floor. The bound is physical because the flux-form and vector-invariant formulations are supposed to give the same viscous dissipation for the same coefficient, so the answer is pinned twice over, and each fault above displaces it by parts in a hundred or worse. It is achievable at a short window because the only tolerance-bearing step is the barotropic solve, and the deck sets cg2dTargetResidual=1e-11, tight enough that the residual falls well past the threshold in a fixed number of iterations and the solve contributes no realistic iteration-count sensitivity; everything else in the step, the viscosity formulas, the advection with its continuous flux limiter and the implicit vertical solves, is fixed-length direct arithmetic with no convergence test, and the run is a single process with a deterministic tile sweep, so two runs of the same build agree bit for bit and the whole measured spread is the amplification of the deliberate two-ulp change. Two hours is also short compared with the days it takes a 1 km front on an f-plane at f0=7.29e-5 to roll up into eddies, so the comparison is made on a laminar adjusting front rather than on a turbulent field, which is what keeps a pointwise rule honest. The measured behaviour of this experiment is the governing fact for this check. A native window scan on the x86_64 host on 2026-09-02, using the sibling deck input.QGLthGM and a one-ulp variant of viscC2LeithQG, found the worst relative spread in salinity growing steadily and smoothly with the window: 7.5e-10 at 6 steps, 7.8e-9 at 12, 1.4e-8 at 24, 4.7e-8 at 36 and 9.5e-8 at 48. That is continuous amplification, not a threshold flipping, and it has two sources that every MLAdjust deck shares. The first is the closure itself: the viscosity is a function of the flow gradients and the viscosity in turn sets the flow gradients, so a perturbation feeds back on itself every step through pkg/mom_common/mom_calc_visc.F. The second is the spice tracer: salinity is stepped with sBeta=0, so it carries a finite vertical gradient across interfaces where the temperature gradient, and hence the density gradient, is neutral, and the strict sign test of model/src/calc_ivdc.F can flip such an interface between a vertical diffusivity of 1e-5 and 10 m2/s while the temperature flux stays negligible. That is why salinity, not temperature, carries the largest spread. The same two mechanisms are present in this deck with the same grid, the same initial front, the same ivdc_kappa and the same class of flow-dependent viscosity, so the same amplification must be expected until it is measured here, and the check is graded over 6 steps, two hours, half the upstream twelve-step window, where the sibling's spread sat thirteen times inside the rule, and is flagged chaotic. The scan to run on this deck is the same one: worst relative spread per field at 6, 12, 24, 36 and 48 steps against a two-ulp variant. If it turns out flatter than the sibling's, the window can be lengthened to the upstream twelve; it must not be lengthened on the strength of the argument alone.
Faults: This check is the flux-form counterpart of the vector-invariant base deck, so it catches faults that only the flux-form operator carries. Dropping the metric terms of the flux-form Laplacian in mom_u_del2u.F and mom_v_del2v.F changes the viscous tendency near the walls by tens of percent and the velocity field by parts in 1e-2 within two hours. Omitting the side drag that no_slip_sides turns on, which is only active in this deck and in the three harmonic ones, changes U along the northern wall by O(1). Getting the grid-scale power of the biharmonic Leith coefficient wrong changes VA4DLTH and VA4ZLTH by an order of magnitude. Reading the pickup with the wrong record order, which its meta file guards against with a nine-field field list, would be an O(1) failure at the first step. Single-precision viscosity leaves around 1e-7 relative in the velocity field.

## Evidence

The overlay supplies its own data, eedata and the pickup; it has no data.pkg or data.gmredi, so input/data.pkg (useMNC and useDiagnostics, no GMRedi) and input/data.diagnostics apply. pickup.0000000036 (2527200 bytes: 243 records of 50x26 real*8, that is nine fields Uvel, Vvel, Theta, Salt, GuNm1, GvNm1, EtaN, dEtaHdt, EtaH) and its meta file must be copied; the binary carries no .data suffix, which works because pkg/mdsio/mdsio_read_field.F checks for a global file under the plain name first. nIter0=36, so the final dump is written at iteration 42. The deck still names bathyFile, hydrogThetaFile and hydrogSaltFile, so topo_sl.bin is read for the geometry; the temperature and salinity files are superseded by the pickup but are kept. data.pkg sets useMNC=.TRUE. and must be turned off (no NetCDF in the image); data.mnc is then unread and is kept only so the deck stays recognisable. The initial fields thetaInitial.bin, spiceInitial.bin and topo_sl.bin (all real*8, 50x26x40x8 and 50x26x8 bytes) and data.diagnostics come from input/. That data.diagnostics sets dumpAtLast=.TRUE., so momDiag (momKE, momHDiv, momVort3, Strain, Tension, Stretch) and viscDiag (twenty-six viscosity fields: the harmonic and biharmonic viscosities on divergence and vorticity points and their maximum, minimum, Leith, Leith-divergence, QG-Leith and Smagorinsky contributions) are written to the run directory at the final iteration and are graded; their nominal frequency of 864000 s is 720 steps and never fires inside the window, so these are partial-window averages, which is deterministic and fine. The per-level statistics stream at stat_freq=7200 s writes plain text with diagSt_mnc=.FALSE. and is not collected. There is no diagMdsDir, so no directory has to be created. pkg/flt is compiled into packages.conf but useFLT is not set, and pkg/exch2 is compiled and builds its default topology from SIZE.h with no data.exch2, exactly as upstream. cg3dMaxIters and cg3dTargetResidual are set in the deck but nonHydrostatic is not, so cg3d never runs. eedata sets nTx=nTy=1. readBinaryPrec and writeBinaryPrec are both 64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: the optimised gfortran build and the IEEE -O0 build of the same source, run natively on the x86_64 host on 2026-09-02, differ on this deck by at most 1.5e-07 in absolute terms, 7.9e-04 of the bound (in viscDiag); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 1.2e+05 of the bound (FAIL), and the variant parameter off by five percent 1.6e+07 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.4 s natively.
