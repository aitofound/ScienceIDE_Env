# mladjust-leith-vort-div

Upstream test: `code/mitgcm/verification/MLAdjust/input.AhVrDv`. Policy: `pointwise`.

## The test

Harmonic Leith viscosity in the vorticity-divergence formulation. `run.sh` builds one MITgcm executable for this
configuration with the tree's own `tools/genmake2` (the build configuration
under `mods/`: `SIZE.h`, `packages.conf` and the option headers of the
upstream experiment, gfortran optfile `linux_amd64_gfortran`, one process,
tiles only), then runs it on the deck under `ic/<ic>/`. Configuration:
verification/MLAdjust: a 50x26x40 zonally re-entrant channel closed by a wall at the northern edge (four tiles of 25x13 under pkg/exch2, uniform 1 km horizontal spacing and forty uniform 5 m levels, 52000 cells and the largest grid in this module's suite), started from a mixed-layer density front given by thetaInitial.bin with salinity carried as a passive spice tracer (spiceInitial.bin, sBeta=0) and a flat bottom from topo_sl.bin, with no forcing of any kind, f-plane at f0=7.29e-5, a linear equation of state, third-order direct-space-time flux-limited advection for both tracers, vertical viscosity viscAr=5e-5, ivdc_kappa=10 with implicit diffusion for convection, useJamartWetPoints, stagger time stepping, an implicit free surface with cg2dTargetResidual=1e-11 and no explicit horizontal background viscosity at all, so that the entire lateral momentum mixing is whatever the flow-dependent closure returns; the input.AhVrDv overlay keeps vector-invariant momentum with the default vorticity and divergence formulation of the viscous terms and the full Leith stencil (useFullLeith=.TRUE.), but makes the viscosity harmonic instead of biharmonic, viscC2leith=1.85 and viscC2leithD=1.85 with a harmonic Smagorinsky term at viscC2smag=1 capped by viscAhGridMax=1 and no background viscAh, and it leaves no_slip_sides at its default true so that side drag acts on the walls; it is therefore the exact harmonic counterpart of the biharmonic base deck and the exact vorticity-divergence counterpart of the strain-tension deck, which is what makes the three of them a useful triangle; the window is 6 steps of 1200 s, two hours, half the upstream twelve-step window and a small fraction of the ten-day endTime the base deck records as its production option, kept short for the measured reason given in the warrant..

The production path it forces: pkg/mom_common/mom_calc_visc.F forming the harmonic Leith, Leith-divergence and Smagorinsky coefficients on vorticity and divergence points, and the vorticity-divergence branch of pkg/mom_vecinv (mom_vi_hdissip.F with mom_vi_del2uv.F) applying them, with model/src/calc_ivdc.F, model/src/impldiff.F and the third-order flux-limited tracer advection of model/src/gad_dst3fl.F..

Runtime knobs (`run.sh --help`): `SAB_STEPS` (default 6, the graded
value; the upstream deck runs 12 steps of 1200 s) scales the
run linearly, and `SAB_BUILD_JOBS` (default 4) only the build. Expected run
time on the declared resources, build excluded: about 3 s;
the per-check build (roughly 40 s on an x86_64 host) is reported by `run.sh`
as `SAB_BUILD_SECONDS` and does not count against the suite budget.

## The two initial conditions

`ic/nominal` is the upstream deck, assembled as `testreport` assembles it
(the experiment's `input/`, the input.AhVrDv/ overlay),
with these deck edits: `nTimeSteps` set to the graded window, `dumpFreq`,
`pChkptFreq` and `chkptFreq` set to zero and `dumpInitAndLast=.TRUE.` so that the only
state written is the initial and final dump, and
`writeBinaryPrec=64` so the dump is double precision and `useSingleCpuIO=.TRUE.` so the dump is one global file per field rather than one per tile; `useMNC=.FALSE.` in `data.pkg`; `useSingleCpuIO=.TRUE.` in `data`.

`ic/variant` holds only the deck files that differ, laid over `ic/nominal` by
`run.sh`; the difference is `viscC2leith=1.8500000000000005` in `data` instead of 1.85:
two ulps of the graded precision (binary64) on a parameter that enters the
tendency from the first step, a distinct double, so the two runs differ at
round-off level from the first step. The
spread between them is the check's measured sensitivity under the pass policy
and must stay inside the bound.

## The pass policy

Every cell of every prognostic field in the final state dump must satisfy
|candidate - reference| <= 1e-10 + 1e-08 |reference|.
The relative part is the working bound because the fields span many orders of
magnitude; the absolute part covers cells at or near zero. The observable is every cell of the final state dump plus the momDiag and viscDiag files that dumpAtLast writes at the final iteration, graded relatively with an absolute floor; viscDiag carries the harmonic viscosity on divergence and vorticity points and its Leith, Leith-divergence and Smagorinsky contributions separately, so the check grades the closure term by term rather than only through its effect. The bound is physical because those terms are closed formulas of the resolved gradients with one right answer per cell per step, and each fault above displaces them by parts in a hundred or worse. It is achievable at a short window because the only tolerance-bearing step is the barotropic solve, and the deck sets cg2dTargetResidual=1e-11, tight enough that the residual falls well past the threshold in a fixed number of iterations and the solve contributes no realistic iteration-count sensitivity; everything else in the step, the viscosity formulas, the advection with its continuous flux limiter and the implicit vertical solves, is fixed-length direct arithmetic with no convergence test, and the run is a single process with a deterministic tile sweep, so two runs of the same build agree bit for bit and the whole measured spread is the amplification of the deliberate two-ulp change. Two hours is also short compared with the days it takes a 1 km front on an f-plane at f0=7.29e-5 to roll up into eddies, so the comparison is made on a laminar adjusting front rather than on a turbulent field, which is what keeps a pointwise rule honest. The measured behaviour of this experiment is the governing fact for this check. A native window scan on the x86_64 host on 2026-09-02, using the sibling deck input.QGLthGM and a one-ulp variant of viscC2LeithQG, found the worst relative spread in salinity growing steadily and smoothly with the window: 7.5e-10 at 6 steps, 7.8e-9 at 12, 1.4e-8 at 24, 4.7e-8 at 36 and 9.5e-8 at 48. That is continuous amplification, not a threshold flipping, and it has two sources that every MLAdjust deck shares. The first is the closure itself: the viscosity is a function of the flow gradients and the viscosity in turn sets the flow gradients, so a perturbation feeds back on itself every step through pkg/mom_common/mom_calc_visc.F. The second is the spice tracer: salinity is stepped with sBeta=0, so it carries a finite vertical gradient across interfaces where the temperature gradient, and hence the density gradient, is neutral, and the strict sign test of model/src/calc_ivdc.F can flip such an interface between a vertical diffusivity of 1e-5 and 10 m2/s while the temperature flux stays negligible. That is why salinity, not temperature, carries the largest spread. The same two mechanisms are present in this deck with the same grid, the same initial front, the same ivdc_kappa and the same class of flow-dependent viscosity, so the same amplification must be expected until it is measured here, and the check is graded over 6 steps, two hours, half the upstream twelve-step window, where the sibling's spread sat thirteen times inside the rule, and is flagged chaotic. The scan to run on this deck is the same one: worst relative spread per field at 6, 12, 24, 36 and 48 steps against a two-ulp variant. If it turns out flatter than the sibling's, the window can be lengthened to the upstream twelve; it must not be lengthened on the strength of the argument alone.
Faults: Because this deck differs from the base deck only in the order of the operator and from the strain-tension deck only in the formulation, it isolates both. Getting the harmonic grid-scale power wrong (the cube of the grid scale over pi, against the fifth power in the biharmonic case) changes VAHDLTH and VAHZLTH by an order of magnitude and the velocity field by parts in 1e-2 within two hours. Evaluating the divergence-point coefficient with the vorticity-point stencil, or vice versa, changes VISCAHD relative to VISCAHZ by tens of percent while leaving their sum plausible, which is the sort of fault only a check that grades both fields separately can catch. Dropping the Leith-divergence term leaves the divergent modes undamped and changes momHDiv by parts in 1e-1. Omitting the side drag changes U along the northern wall by O(1). Single-precision viscosity leaves around 1e-7 relative in the velocity field.

## Evidence

The overlay supplies only data and the two eedata files; it has no data.pkg, so input/data.pkg (useMNC and useDiagnostics, no GMRedi) and input/data.diagnostics apply. nIter0=0 and there is no pickup, so the run starts from rest and the final dump is written at iteration 6. The biharmonic entries of viscDiag are identically zero here and match trivially. data.pkg sets useMNC=.TRUE. and must be turned off (no NetCDF in the image); data.mnc is then unread and is kept only so the deck stays recognisable. The initial fields thetaInitial.bin, spiceInitial.bin and topo_sl.bin (all real*8, 50x26x40x8 and 50x26x8 bytes) and data.diagnostics come from input/. That data.diagnostics sets dumpAtLast=.TRUE., so momDiag (momKE, momHDiv, momVort3, Strain, Tension, Stretch) and viscDiag (twenty-six viscosity fields: the harmonic and biharmonic viscosities on divergence and vorticity points and their maximum, minimum, Leith, Leith-divergence, QG-Leith and Smagorinsky contributions) are written to the run directory at the final iteration and are graded; their nominal frequency of 864000 s is 720 steps and never fires inside the window, so these are partial-window averages, which is deterministic and fine. The per-level statistics stream at stat_freq=7200 s writes plain text with diagSt_mnc=.FALSE. and is not collected. There is no diagMdsDir, so no directory has to be created. pkg/flt is compiled into packages.conf but useFLT is not set, and pkg/exch2 is compiled and builds its default topology from SIZE.h with no data.exch2, exactly as upstream. cg3dMaxIters and cg3dTargetResidual are set in the deck but nonHydrostatic is not, so cg3d never runs. eedata sets nTx=nTy=1. readBinaryPrec and writeBinaryPrec are both 64. This deck sets neither globalFiles nor useSingleCpuIO, so MITgcm's mdsio writes one file per tile and names the final dump <field>.<iteration>.001.001.data (pkg/mdsio/mdsio_write_field.F, the 'Case of 1 file per tile' branch), which the generator's collector and validate.py, both of which match ^<field>.<10 digits>.data$, would not see at all; the extra edit useSingleCpuIO=.TRUE. makes mdsio gather the tiles and write one global file per field, exactly as every sea-ice check's deck does. It is a pure I/O switch and changes no arithmetic; globalFiles=.TRUE. would do the same job for the non-exch2 decks, but useSingleCpuIO is the variant the finished task already exercises.

Floor: the optimised gfortran build and the IEEE -O0 build of the same source, run natively on the x86_64 host on 2026-09-02, differ on this deck by at most 9.7e-14 in absolute terms, 4.4e-04 of the bound (in viscDiag); the two builds pass each other under the rule. Faults, same build with one parameter changed: the cg2d target residual loosened to 1e-3 uses 3.1e+04 of the bound (FAIL), and the variant parameter off by five percent 7.9e+06 of the bound (FAIL). Measured run time of the nominal deck, build excluded: 0.4 s natively.
